# English Companion v0.1 产品需求文档（PRD）

- **版本：** v0.1 Draft
- **日期：** 2026-08-11
- **产品负责人：** Kris
- **文档维护：** Hermes
- **目标平台：** macOS
- **当前阶段：** 产品范围和 Quick Panel 视觉方向已确认；Chrome 真实选区已验证，待真实 Provider、其余选区表面和 Workspace
- **技术架构：** AppKit shell + SwiftUI UI + 本地 SQLite；无 WebView

> 本文档定义 v0.1 要解决的问题、交互和验收标准，不代表已经授权开始实现。

## 1. 产品概述

English Companion 是一款轻量、键盘优先的 macOS 中英沟通与学习助手。核心交互不是传统应用窗口，而是类似 Raycast 的无标题栏输入浮层：快捷键唤起、输入或接收选中文字、结果向下展开、按 `Esc` 消失。

“轻量”指交互简单、运行时开销低、无浏览器运行时和空闲时低资源占用；由于完整 ECDICT 随 App 发布，安装包不以极小体积为第一目标。

它主要帮助用户：

1. 将中文快速翻译为简短、自然、适合 Slack/WhatsApp 的英文；
2. 理解香港同事发来的英文，并获得可直接发送的建议回复；
3. 优化英文、中文以及大量中英混杂的工作消息；
4. 离线查询完整 ECDICT 词典；
5. 将真实沟通中的翻译、错误和词汇保存在本机，为后续复习、Anki 和 Markdown 导出提供数据。

### 产品承诺

> 在几秒内，把眼前的文字变成我能理解或能直接发送的内容，并让真实工作沟通自然沉淀为英语学习材料。

## 2. 目标用户与场景

### 核心用户

经常与香港同事用英文沟通、英语表达信心不足，但希望在完成工作的同时逐步提升英语的中文用户。

### 高频场景

- 在 Slack、WhatsApp、邮件或浏览器中选中英文消息，快速查看中文意思和建议回复；
- 选中自己写的英文，快速纠正语法并改成自然表达；
- 选中大量中英混杂的草稿，将其整理成连贯英文；
- 选中中文，生成可直接发送的英文并通过中文回译确认含义；
- 查询英文单词或短语，查看完整本地词典信息；
- 回顾以前翻译过、写错过或反复查询的内容。

## 3. 产品目标

### v0.1 目标

- 快速完成中文↔英文职场沟通；
- 提供明确的“翻译”和“优化”两种操作；
- 支持划词、剪贴板和全局快捷键；
- 支持 DeepSeek、豆包和 OpenAI；
- 提供完整离线 ECDICT 查询；
- 将历史、术语和学习数据结构化保存在本机；
- 保持应用交互简单、运行轻量。

### 非目标

v0.1 不做：

- OCR 或截图翻译；
- 浏览器扩展；
- 团队协作；
- 用户账户和云同步；
- 有道 API；
- 多家在线词典聚合；
- 完整 Anki 复习系统；
- 自动同步 Obsidian、Notion 或远程知识库；
- 专门的粤语口语理解模式；
- 大量复杂设置。

## 4. 产品原则

1. **快捷键优先。** 核心流程不依赖鼠标。
2. **输出必须可直接发送。** 不把选择和重写工作重新交给用户。
3. **事实不可漂移。** 不修改姓名、日期、数字、URL、技术术语和承诺强度。
4. **默认简短口语化。** 中文→英文适合 Slack/WhatsApp，不使用过度正式表达。
5. **学习信息保持可见。** 优化结果同时展示原文、修改版和详细说明。
6. **本地数据为主。** 历史、术语和复习数据以本地结构化数据库为事实来源。
7. **云端调用透明。** 用户知道使用哪个 Provider，API Key 仅保存在 Keychain。
8. **不复制 Easydict 的复杂度。** 聚焦沟通、优化、查词和学习沉淀。

## 5. 信息架构

应用采用两个互补形态，共享同一份数据和任务状态：

1. **Quick Panel / 快捷浮层（默认）**
   - 翻译结果
   - 优化结果
   - 词典结果
2. **Workspace Window / 工作台窗口（持久）**
   - 当前翻译、优化或词典任务的完整内容
   - 历史记录
   - 个人术语表
   - 长文本和详细说明
3. **设置窗口**
   - 快捷键
   - Provider 与模型
   - API Key
   - 历史与隐私
   - 导出
4. **菜单栏入口**

快捷浮层是日常使用的核心；工作台窗口用于需要停留、搜索、编辑、对比和管理的任务。两者不是两套产品，不得复制或分叉业务逻辑。

## 6. 核心交互

### 6.1 两个明确功能

- **翻译 / Translate**
- **优化 / Improve**

产品不得仅凭英文输入自动猜测用户是要翻译还是优化；功能由快捷键或界面明确决定。

### 6.2 两个全局快捷键

用户在设置中分别录制：

- 翻译快捷键
- 优化快捷键

不预先锁定具体组合，避免与系统和现有应用冲突。

### 6.3 输入来源优先级

快捷键触发后：

1. 优先读取当前应用选中的文字；
2. 没有可用选区时读取现有文本剪贴板；
3. 两者都没有时打开对应模式并聚焦输入框。

结果窗口必须显示来源标签：

- `Selection`
- `Clipboard`
- `Typed`

若通过模拟复制获取选区，必须只接受本次操作后发生变化且读取期间稳定的新文本。由于 macOS general pasteboard 不提供原子条件写，v0.1 不自动恢复旧剪贴板，避免在恢复时覆盖用户或 clipboard manager 的并发更新；结果来源必须明确显示为 `Clipboard`。

### 6.4 Raycast 风格输入浮层

- 使用无标题栏、无红黄绿窗口按钮的特殊浮动面板，而不是标准 App 窗口；
- 位于当前活动屏幕的上方中央区域，视觉和操作方式接近 Raycast；
- 最上方始终是输入区域，显示当前文字并允许用户继续编辑；
- 不显示“翻译 / 优化”切换 Tab；用户触发的全局快捷键已经决定本次任务模式；
- 输入区仅保留模式图标和文字，最大化可编辑空间；
- 当前模式、输入来源（Selection/Clipboard/Typed）和 Provider 等次要信息放在底部状态栏；
- 触发后立即显示浮层和加载状态，结果在输入框下方向下展开；
- 内容较长时只滚动结果区域，不让整个面板无限增高；
- 同一时间只存在一个浮层；新任务复用并更新现有浮层；
- `Esc` 隐藏浮层并将操作返回之前应用；
- 不因失去焦点自动隐藏；
- 不自动覆盖剪贴板；
- Copy 按钮或 `⌘C` 复制主结果；若用户正在结果文本中选择内容，`⌘C` 应保持标准行为并复制选中内容；
- 浮层不作为普通主窗口长期占据桌面或 Dock 工作流。

### 6.5 双形态切换

#### Quick Panel

- 全局快捷键默认唤起；
- 适合选中文字、快速翻译/优化、查词、复制并离开；
- 短暂、紧凑、键盘优先；
- `Esc` 立即隐藏。

#### Workspace Window

- 是可调整大小、可持续停留的普通 macOS 窗口；
- 适合长文本、完整优化说明、历史搜索、术语管理和后续导出；
- 可以承接 Quick Panel 当前任务，保留输入、结果、Provider 和历史记录；
- 关闭 Workspace Window 不应清除历史或影响后台菜单栏能力。

#### 切换规则

- Quick Panel 底部提供“在窗口中打开”操作；
- 内容很长时仍先在浮层显示，不自动强制跳窗，只提示可在窗口中打开；
- 从浮层进入窗口时不得重新调用模型或丢失结果；
- Workspace Window 可通过菜单栏、历史入口或浮层操作打开；
- 两个形态共享同一个任务 ID、本地数据库和 Provider 配置。

## 7. 翻译功能需求

### TR-01 中文→英文

输入简体或繁体中文时：

- 输出一条简短、自然、适合 Slack/WhatsApp 的英文；
- 保留事实、术语和承诺程度；
- 同时输出中文回译；
- 中文回译必须忠实反映生成英文的实际含义；
- 英文主结果提供 Copy；
- 支持进一步操作：更短、更礼貌、解释措辞。

#### 展示结构

```text
英文译文                         Copy
Do you need anything from our side?

中文回译
你需要我们这边提供什么吗？
```

### TR-02 英文→中文

输入英文句子或段落时：

- 输出自然、准确的中文；
- 同时输出一条简短的建议英文回复；
- 建议回复单独提供 Copy；
- 不得擅自承诺日期、完成状态或行动；
- 若无需回复，应明确显示“无需回复”，可选提供简单确认语。

#### 展示结构

```text
中文翻译
他在问迁移后能否验证系统是否正常。

建议英文回复                     Copy
Sure, I’ll verify it after the migration and let you know.
```

### TR-03 中英混杂翻译

- 根据整体语义确定目标结果；
- 保留已有英文项目名、缩写、命令、URL 和技术术语；
- 不重复翻译已经正确的标识符。

### TR-04 繁体中文

- 简体和繁体中文均为正式支持输入；
- 输出中文默认跟随应用语言设置；
- 粤语口语仅作模型最佳努力，不提供专门模式。

## 8. 优化功能需求

### IM-01 英文优化

同时展示：

1. 原文；
2. 优化后的英文；
3. 详细逐项说明。

说明必须区分：

- `grammar`：明确语法错误；
- `naturalness`：自然度改进；
- `tone`：语气调整。

不得将纯风格偏好描述为硬性语法错误。若原文已经自然，应明确说明，不得为制造差异而过度改写。

### IM-02 中文优化

纯中文输入：

- 输出更清晰、简洁、自然的中文；
- 不自动翻译成英文；
- 保留事实和技术名词。
- 至少展示原文和优化后的中文；解释区沿用 Improve 的修改分类，但允许在没有实质修改时明确说明“无需调整”。

### IM-03 中英混杂优化

大量中英混杂输入：

- 输出一条完整、自然、可直接发送的英文；
- 中文片段作为意图和上下文；
- 保留已有英文名称、项目名、缩写、命令和 URL；
- 同时展示原文、英文优化版和中文逐项说明。

## 9. ECDICT 本地词典

### DI-01 数据源

- 使用完整 ECDICT；
- 转换为应用内 SQLite；
- 完整词库随应用发布；
- 安装后立即离线可用；
- 不需要首次启动下载；
- 不使用有道词典 API。

### DI-02 自动触发

在翻译模式下：

- 输入英文单词或 ECDICT 可识别短语时自动显示词典卡片；
- 不增加第三个顶层模式或第三个快捷键；
- 词形变化应解析到 lemma，同时保留原查询形式；
- 本地无匹配时自动降级为普通英译中；
- 长句和段落直接进入普通翻译。

### DI-03 卡片内容

展示该词条所有可用 ECDICT 字段：

- 查询形式和 lemma；
- 音标；
- 词性；
- 完整中文释义；
- 完整英文定义；
- 单词变形；
- BNC 和当代语料词频；
- Collins、Oxford 标记；
- IELTS、CET4、CET6、GRE 等考试标签；
- 数据中存在的例句、detail 或音频信息。

空字段不显示，但已有内容不得静默截断。长内容使用垂直滚动。

### DI-04 发音

- 优先使用 macOS 系统发音；
- 不依赖 ECDICT 的音频覆盖率；
- 发音失败不影响释义展示。

## 10. 模型 Provider

### PR-01 支持范围

v0.1 同时支持：

- DeepSeek
- 豆包 / Volcengine Ark
- OpenAI

三者完成后再通过真实盲测选择默认模型。未选中的 Provider 仍保留为可配置选项。

### PR-02 统一能力

三个 Provider 必须满足相同产品契约：

- 中文→英文＋中文回译；
- 英文→中文＋建议回复；
- 英文/中文/混合文本优化；
- 结构化错误说明；
- 流式或渐进状态反馈；
- 错误可恢复。

### PR-03 BYOK

- 用户填写自己的 API Key；
- Key 存储在 macOS Keychain；
- 不写入配置文件、日志、历史或导出文件；
- 每个 Provider 独立保存凭据；
- 支持配置模型名称或 Endpoint ID；
- v0.1 不需要项目自建后端。

### PR-04 默认模型选择

采用任务场景盲测，而不是通用排行榜：

- 含义和事实忠实度；
- 可直接发送性；
- Slack/WhatsApp 自然度；
- 语法与解释准确性；
- 建议回复合理性；
- 延迟；
- 成本。

质量优先，延迟和成本作为次要标准。

## 11. 历史与本地数据

### HS-01 默认保存

默认在本机保存：

- 原始输入；
- 输入来源；
- 模式；
- Provider 和模型标识；
- 主结果和次级结果；
- 优化修改项；
- 最终复制文本；
- 查词信息；
- 时间和标签。

### HS-02 保留策略

- 默认永久保留；
- 直到用户主动删除；
- 不执行自动过期清理；
- 支持逐条删除；
- 支持确认后的清空全部；
- 支持单次“不保存”；
- 支持关闭历史或临时隐私模式。

### HS-03 本地事实来源

本地结构化数据库是历史、术语和学习数据的事实来源。v0.1 不同步到云端知识库。

## 12. 自动个人术语表

### GL-01 自动学习

从以下内容识别高价值术语：

- 同事姓名；
- 项目名；
- 产品名；
- 缩写；
- 技术术语；
- 用户最终复制和采用的表达。

### GL-02 学习规则

- 优先学习最终复制文本；
- 记录出现次数和上下文；
- 一次性拼写错误不得覆盖稳定术语；
- 将相关术语注入翻译/优化请求；
- 术语可查看、编辑、停用和删除；
- API Key、Token、密码和疑似秘密不得进入术语表；
- 术语表默认只保存在本机。

## 13. 学习与导出

### v0.1 要求

- 数据以结构化方式保存；
- 能标记值得复习的记录；
- 能统计查词和错误类型；
- 数据结构必须支持未来导出。

### 后续版本

- Anki 导出；
- Markdown 导出；
- 每周复习；
- 重复错误统计；
- 高频短语和词汇复习卡。

Anki 和 Markdown 导出是既定方向，但不作为 v0.1 首次可用版本的发布阻塞项。

## 14. 设置

v0.1 设置至少包含：

1. 翻译快捷键录制；
2. 优化快捷键录制；
3. 默认 Provider；
4. Provider 模型或 Endpoint；
5. API Key 状态与测试连接；
6. 默认语气；
7. 历史开关、隐私模式和清空数据；
8. 个人术语表管理；
9. 关于、ECDICT 来源和许可证。

## 15. 状态与错误处理

### 输入为空

若选区和剪贴板均无文本，打开对应模式并聚焦输入框。

### 剪贴板来源

使用剪贴板时必须显示来源，降低误用旧内容的风险。

### Provider 未配置

- 显示清晰错误；
- 提供前往设置的入口；
- 不丢失当前输入。

### API 失败

- 显示 Provider 和可理解的错误；
- 允许重试；
- 允许切换其他已配置 Provider；
- 不把失败响应写成成功历史。

### 新请求覆盖旧请求

- 新快捷键任务取消或废弃旧请求；
- 旧响应返回后不得覆盖新任务结果。

### ECDICT 无结果

自动转为普通英译中，并清楚标记结果类型为 Translation。

## 16. 隐私与安全

- API 凭据只进入 Keychain；
- 日志和错误中不得出现完整 Key；
- 历史数据库默认只保存在本机；
- 不自动同步工作消息；
- 清空数据必须明确确认；
- 提供本地敏感内容识别和可选脱敏；
- 不将疑似秘密写入术语表或复习导出；
- Provider 调用必须对用户透明。

## 17. 非功能需求

### 性能目标

- 快捷键触发后应立即显示窗口或明确的加载状态；
- 本地词典查询应让用户感知为即时；
- UI 不因云端请求阻塞；
- 空闲时不持续高 CPU；
- 同一时刻只处理一个前台交互任务。

### 可用性

- 核心流程全键盘可完成；
- 主要按钮有明确可访问名称；
- 中英文、长文本和动态字体可正常布局；
- 支持中文输入法和 IME；
- 结果区可选择和复制文本。

### 兼容性

- 目标为现代 macOS；
- 最低系统版本在发布前确定；
- AppKit 负责窗口与系统集成，SwiftUI 负责全部产品界面。

## 18. 验收标准

### 翻译

- 中文输入产生英文主结果和中文回译；
- 英文输入产生中文翻译和建议回复；
- 数字、日期、URL、姓名占位符和术语保持一致；
